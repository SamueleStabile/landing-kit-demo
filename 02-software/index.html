1:storagecopy-on-write

It copies pointers, not rows.

A branch starts as a second set of references to the same storage extents. Nothing is duplicated until the branch writes, and then only the page it touched. This is why the fork time barely moves between a 2 GB database and a 2 TB one.

  • shared extent — one copy on disk
  • written by the branch — copied on write

2:policypolicy.umbra.toml · committed

Anonymisation is a file in your repo.

Not a script someone remembers to run. The policy lives beside your migrations, ships through review, and the branch refuses to open an endpoint if a column it covers is missing.

3:reviewreverse video

The branch is what review actually reads.

Every pull request opens with a live endpoint and a plan of what the migration does to real shapes and real volume. A destructive change without a backfill does not get a green check.
